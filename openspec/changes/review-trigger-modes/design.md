## Context

The baseline webhook admits exactly opened, synchronize, reopened, and ready_for_review. Ready normalizes stale draft metadata to false. The existing PR/head Durable Object suppresses an ordinary terminal restart, while the webhook does not consult completed checks when local history is absent. Consumer PR 2026-09-11 motivates avoiding repeated automatic work; it does not establish the deployed local-record state or require changing the PR diff base.

## Goals / Non-Goals

Preserve default action coverage, strict dual-reader acceptance, base-SHA anchoring, publication behavior, and draft silence. Enable explicit human reruns and same-PR/head joins without duplicate sandboxes or replay-triggered reruns. Cross-PR same-commit concurrency and strict cross-PR exclusion are out of scope: different PRs can have different bases and diffs. This feature adds no repository-wide scheduler, durable queue outbox, or new alarm role. Do not add a CLI mention path or behind-base policy.

## Decisions

- Extend the nested trigger model with the four baseline actions, two comment surfaces, and eight GitHub author associations. Empty selection lists are valid and select nothing. Both event paths and dedupe default on. `rvw policy lint [PATH] [--json]` warns with `empty-pull-request-actions` and exits zero for `pull_request.enabled: true` with `actions: []`; its default path is `.rvw/policies/auto.yaml`, and malformed or missing policy remains an error with exit 2.
- Keep trigger and publication policy fetches separate with their existing limits and failure classifications. An invalid trigger policy keeps the existing automatic review fallback without applying event-selection or completed-head filters. CLI rule/draft and force behavior stays independent of webhook event selection.
- Preserve top-level `summary.trigger`: boolean skip facts still load, and closed string reasons are `events_disabled`, `action_not_selected`, `same_head_reviewed`, and `in_flight_same_head`. Add `source` (default pull_request), `actor` (null), and positive `comment_id` (null). Bind facts to reviewed base/head anchors in both readers.
- Scope completion to `(installation, repository, PR, head)`. Consult only the existing executor address `i:r:p:h`, then paginated own-App checks on that commit if durable evidence is missing or inconclusive. A check must have numeric App-ID equality, the exact head, completed status, a string external ID excluding `:trigger-skip`, and no truthy trigger skip. Recoverable job identity is authoritative: parse `external_id` as `installation:repo:pr:sha` and recover any structured `job_id` or `artifact_key` identities. At least one identity must match the requested job, and every recovered identity must agree with that requested installation, repository, PR, and head. Reject contradictory identities even if `pull_requests[]` lists this PR. That array describes commit/branch associations and does not establish review ownership; if no job identity is recoverable, fail open. Commit association alone never suppresses a review.
- Retain durable `reviewCompleted: true` across later reruns. Set it only for a terminal completed mapping with a defined pass/block outcome, parseable summary, positive valid lanes, and no trigger skip. Legacy records lacking the marker count only in completed state with success/failure conclusion and no trigger skip; failed state and neutral legacy records are inconclusive. New check output requires structured `review_completed: true`; explicit false rejects. Legacy check fallback additionally requires facts job/artifact identity matching the requested job, positive valid lanes, and a known English/Korean pass/block reason suffix. Internal consistency between legacy facts and the check's own external ID is insufficient if they identify another PR. Mere check completion/conclusion does not establish a review. API errors or missing/inaccessible history log and fail open.
- Keep execution at `i:r:p:h` with its existing job/artifact identity. The executor's real serialized `start()` and durable delivery/mention identities decide reruns and joins. New mentions bypass completed-head dedupe; dedupe-disabled distinct automatic events and existing check rerequests can rerun terminal work. A nonterminal execution for this PR/head joins a mention with `in_flight_same_head`, still acknowledging eyes. The webhook may use status as a join hint but still queues the pinned mention for the real executor start path to consume its identity durably; that bookkeeping delivery creates no second sandbox and cannot become a rerun if the active execution finishes first. Pending cleanup/check-update obligations must settle before a terminal record is replaced; old sandbox/process/check identifiers remain available until then. Queue retries use the existing consumer lifecycle; no separate reservation, outbox, or scheduling object is introduced.
- Keep a comment-scoped `mention:i:r:<surface>:<commentId>` object in the existing namespace. Its `mention` record stores the first validated message transactionally and has no alarm or lifecycle. Redelivery after a push therefore targets the original executor, while a genuinely new comment targets the new head. The executor retains handled identities so a joined or previously accepted comment cannot restart work later.
- Reject unsupported actions and non-PR issue comments before App API access. Reject a body with no `@` before identity lookup regardless of cache state. Cache authenticated App metadata in module scope for five minutes across requests; an eligible cold isolate or expired cache may make one `GET /app` to learn the current slug. When an unexpired cached slug is available, require a case-insensitive literal `@<slug>` substring before an API call or Markdown parse. An expired identity is unavailable to the precheck so a new-slug candidate can reach authenticated refresh; apply the literal precheck after refreshing too. An identity failure returns 204 with a structured log, never 400. Reuse one `markdown-it@15.0.2` parser per isolate.
- Whole-token mention matching uses adjacent visible text across inline formatting and link-label boundaries within each inline block. Thus `foo**@slug**` and `@slug**bot**` reject, while `**@slug**`, `(@slug)`, `@slug,`, `@SLUG`, and `[@slug](url)` match. Reject a slash immediately after the slug so `@slug/review` remains a team mention; sentence suffixes `.`, `,`, `?`, `!`, `'s`, and `:` remain accepted. CommonMark can leave the asterisks in `foo**@slug**` as literal text instead of formatting tokens, so the whole-token rule also excludes a literal `*` immediately before the at-sign. Exclude inline/fenced/indented code, inline/block HTML, and all blockquotes. A fresh unquoted mention after a quote can still match. Strikethrough and curly quotation marks do not exclude a visible whole mention.
- Reject Bot authors and the authenticated App's own identity irrespective of association policy. Read the open PR and base-ref mention policy with the installation token. Apply enabled/surfaces/allow, but let authorized mentions bypass draft/rule filters. Obtain the normal review token before optional Issues write scope. On 403/422 optional scope fallback uses base permissions; reaction errors log without cancelling review. The manifest retains both comment subscriptions and Issues write.

## Risks / Trade-offs

- GitHub history can omit old checks; unavailable evidence permits automatic admission and does not prove a review was never completed.
- Same-PR/head serialization does not prevent separate PRs sharing a SHA from executing concurrently.
- Comment pins and handled identities persist without a retention change in this feature; pins have no alarms.
- App identity is unavailable on some requests; returning 204 can lose a mention, which is preferable to making ordinary discussion fail webhook delivery.

## Rollout

Deploy both strict readers before publishing YAML with the new keys. For existing Apps, owners add Issue comment and Pull request review comment subscriptions and approve Issues write; automatic review remains usable before optional reaction permission is granted. Remove new YAML keys before rollback to an older reader. The active change remains delta-only and unarchived until the later archive step synchronizes main requirements.
