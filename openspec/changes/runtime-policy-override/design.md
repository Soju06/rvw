## Context

See proposal.md for the motivation. The evidence is four consecutive production App runs on the consuming repository at `--deadline 900`: the `correctness`, `hygiene`, and `test-integrity` lanes died at the deadline on every attempt after stating that coverage was complete and a final evidence pass was underway, with 35 to 94 tool calls per dead lane versus 5 to 19 for lanes that finished, unchanged by the 0.15.0 prompt budget contract. The policy is a single frozen value object, `CodexRuntimePolicy`, whose packaged default `DEFAULT_CODEX_RUNTIME_POLICY` is `gpt-5.6-sol` / `max` / `detailed` (`src/rvw/runtime_policy.py`); `CodexRuntime(policy=...)` renders it as `--model <m> -c model_reasoning_effort="<e>" -c model_reasoning_summary="<s>"` and records it in `usage.json`. At 0.16.0 every construction site in `src/rvw/cli.py` (`CodexRuntime(mode=..., no_output_seconds=...)` for discovery, tool-less adjudication, agentic expanded adjudication, the stack presence pass, sample, and re-adjudication) omits `policy=` and therefore takes the default; the publication rewriter in `src/rvw/publish.py` does the same. The 0.15.0 `--no-output-timeout` / `RVW_NO_OUTPUT_SECONDS` work established the shape being reused here: resolve once at the CLI boundary, fail closed on a malformed environment value, append the effective value to the canonical command, record it on `RuntimeSettings`. The Worker builds the `rvw run` line in `buildRvwRunInvocation` (`cloud/worker/src/sandbox-auth.ts`, kept import-free because `tests/test_adapter_parity.py` executes it with plain Node type stripping), reads its vars in `requiredConfig` (`config.ts`), renders the review script in `review-job.ts` and the spike script in `routes.ts`, and parses `process.json` in `review-job-contract.ts`. The effort vocabulary is Codex 0.152.0 `ReasoningEffort` (`codex-rs/protocol/src/openai_models.rs` at tag `rust-v0.152.0`): `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, `ultra`, `persistent`, plus a `Custom(String)` passthrough.

## Goals / Non-Goals

Goals: change the model and reasoning effort for one run without a code change, on the CLI and on the App path; make the effective values visible in every artifact a later comparison reads (`usage.json`, `process.json`, `environment.txt`, the canonical command, the check text); keep the packaged default byte-identical so a run that sets nothing is unchanged; reject typos before any runtime work so a misspelt cell cannot silently run the default. Non-goals: changing the default model or effort, lane prompts, the deadline, the watchdog, replica counts, the publication rewriter's policy, `cloud/wrangler.jsonc`, the deploy workflow, Terraform, a model allowlist, the `Custom` effort passthrough, per-lane or per-stage policies, and running the A/B itself.

## Decisions

1. One resolver, at the command boundary. `resolve_codex_runtime_policy(explicit_model, explicit_effort, environ)` resolves each field independently: an explicit option wins and its environment variable is then not consulted; otherwise a present variable; otherwise the packaged default. It returns a `CodexRuntimePolicy` whose `reasoning_summary` stays `detailed`. Every command resolves exactly once and threads the object through `_execute_pipeline(..., runtime_policy=...)`, `_review_pipeline`, `_gate_pipeline`, `_stack_review_pipeline`, `_adjudicate_existing_run`, and `sample`, to all `CodexRuntime` constructions. Retry and coverage redispatch reuse the discovery runtime object inside `rvw.discover`, and initial and expanded adjudication reuse the runtimes the pipeline passes, so there is no hidden construction that could fall back to the default.
2. Validation lives in the resolver, not the value object. `CodexRuntimePolicy` keeps accepting any non-empty effort string because Codex itself accepts a `Custom(String)` effort and a future Codex may add names; the resolver is where an operator's input is checked, and it accepts only the nine named 0.152.0 values (lowercase, after trimming). The message names the offending source (`--reasoning-effort` or `RVW_CODEX_REASONING_EFFORT`, `--model` or `RVW_CODEX_MODEL`) and, for the effort, lists the allowed values. The model has no allowlist: it is any non-empty trimmed string and the proxy decides whether it exists, which is what lets the owner try a `gpt-6` variant without a release.
3. Fail closed the same way `--no-output-timeout` does. `review`, `gate`, `stack review`, `sample`, and `adjudicate` call `_command_runtime_policy(...)` as their first statement, before `_command_host_gate()`, and exit 2 with the resolver's message on stderr. `run` and `auto` resolve inside `_run_command`'s `configuration` stage directly after `no_output_seconds`, so a malformed value finalizes `process.json` with status `invalid`, exit 2, failure code `invalid_configuration`, and a detail naming the option or variable, while the process contract stays intact for the App. `sample` and `adjudicate` gain the options even though they read no watchdog environment: their runs must be attributable to a cell too.
4. Recording is additive. `RuntimeSettings` gains `model` (default `gpt-5.6-sol`) and `reasoning_effort` (default `max`), both `min_length=1`, appended after `reasoning_summary`; `process.json runtime.*` and `environment.txt` (`key=value` per runtime field) therefore carry them, and the schema resource is regenerated. `run` and `auto` append `--model <m> --reasoning-effort <e>` to the canonical command right after `--no-output-timeout <n>`, so `process.json` shows the policy that governed the run even when it came from the environment. `usage.json` already records model and effort from the runtime's policy. Legacy `process.json` without the keys still loads; an empty string is rejected.
5. The publication rewriter keeps the packaged default. Its 60 s prose translation is not a review runtime and is not part of the A/B; letting it follow the override would add a confound (translation quality at `medium`) to a measurement about lane behaviour.
6. The App path uses two optional Worker vars. `RVW_CODEX_MODEL` and `RVW_CODEX_REASONING_EFFORT` are optional (absent means the CLI default, so `cloud/wrangler.jsonc` is untouched), read by `optionalCodexModel` / `optionalReasoningEffort` in `config.ts` with the same fail-closed rule as `RVW_JOB_DEADLINE_MINUTES` (present but empty, whitespace, or off-enum is `ConfigInvalidError`), and included in the frozen `RequiredConfig` only when defined. `buildRvwRunInvocation` appends ` --model '<m>'` and ` --reasoning-effort '<e>'` after `--json`, each only when supplied, and throws on an empty model or off-enum effort so the review script can never carry a value the CLI would reject. `reviewScript(message, deadlineSeconds, {model, reasoningEffort})` renders it. `REASONING_EFFORT_VALUES`, `isReasoningEffort`, and the `ReasoningEffort` type live in the import-free `sandbox-auth.ts`.
7. The spike endpoint takes the cell in a JSON body. `repo` and `target` stay query parameters because the driver already sends them that way; `parseStartOverrides` (import-free `spike-contract.ts`) accepts an optional object with only `model` and `reasoning_effort`, rejects unknown keys (so a typo cannot silently run the default cell), non-objects, arrays, an empty model, and an off-enum effort; malformed JSON or a parse error is a 400 before any sandbox exists. The effective value per field is body override, then Worker var, then undefined. The 202 response gains `model` and `reasoning_effort` (string or null) so the driver's `start.json` names the cell. `drive-spike.sh` POSTs a body built with `jq -n --arg` only when the driver's own `RVW_CODEX_MODEL` or `RVW_CODEX_REASONING_EFFORT` is set; otherwise the request is unchanged.
8. The check text names the cell. `parseProcessResult` accepts optional `runtime.model` and `runtime.reasoning_effort` (non-empty strings; empty is `process runtime settings are invalid`; legacy envelopes still parse), `ProcessResult` and `ReviewResultMapping` carry `runtime: {model, reasoning_effort}` with per-field null, and `diagnosticText` emits `runtime` (null when `process.json` is missing or unparseable). No catalog key is added: the Worker renders no sentence about the policy.

## Risks / Trade-offs

- An operator sets `RVW_CODEX_REASONING_EFFORT` on a host and forgets it, so unrelated runs use the cell → every artifact records the effective values and `run`/`auto` put them in the canonical command, so the drift is visible in the first `process.json`.
- A model string the proxy does not serve fails at the first request → the model is the one field with no allowlist on purpose; the failure is a normal INVALID runtime with its own log, and the value is in `usage.json`.
- Rejecting Codex's `Custom` effort blocks a value Codex would accept → the nine names cover every documented cell; widening is a one-line change to `REASONING_EFFORT_VALUES` (and the mirrored TypeScript array) when Codex names a new one.
- The Worker and CLI enums drift → both are the same nine literals; the adapter-parity test executes `sandbox-auth.ts` with Node against the Python-rendered command, and a mismatch shows as a rejected spike body or a CLI exit 2 with the value in the message.
- The spike body precedence hides a Worker var → the 202 response echoes the effective values and the driver saves it as `start.json`.
- Recording `runtime.model` in check text exposes the model slug → the slug is already in `usage.json` and `environment.txt` under the same artifact key; nothing secret is added.

## Migration Plan

Two staged conventional commits on this branch: `feat(runtime): resolve the Codex model and reasoning effort from CLI or environment` (Python resolver, options, propagation, recording, schema, runtime-contract and operation-modes specs and context), then `feat(cloud): pass model and reasoning effort overrides to the sandbox and spike runs` (Worker vars, script arguments, parser, check text, spike body, driver, README, cloud-app-platform spec and context). Legacy `process.json` loads with the packaged default values. No deployment, push, PR, or archive is part of this work; the change stays unarchived until the A/B has been run and the specs are re-verified against the measured behaviour.
