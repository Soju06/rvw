## Why

Consuming repositories own publication and synthesis choices. The synthesis lane introduced a product-specific Gmail example and rejected legitimate discovery-domain prose; both defects must be corrected while new controls preserve existing defaults.

## What Changes

- Replace product-specific synthesis examples, accept bounded repository examples and allowed terms, and distinguish process vocabulary from source-domain terms.
- Allow repositories to disable synthesis with an explicit persisted status and fallback rendering.
- Honor base-policy publication channels, configurable PASS/BLOCK check conclusions, and severity/count inline placement.
- Localize operator plan/result/thread summaries and gate errors without changing machine reasons.
- Extend strict Python/Worker contracts, shared fixtures, facts, documentation and regression coverage.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `synthesis`: generic/domain-aware voice and optional execution.
- `reporting`: publication channels, inline placement and durable facts.
- `cloud-app-platform`: base-policy channels and check conclusions, shared contracts.
- `operation-modes`: strict publication policy and localized operator output.
- `lane-registry`: anchored presentation and publication controls.

## Impact

Python presentation, synthesis, policy, pipeline, publication and CLI; Worker presentation, review-job and contracts; English/Korean catalogs; schemas and shared fixtures. External registry, webhook, queue-consumer and trigger policy are excluded. No deployment, push or PR.
