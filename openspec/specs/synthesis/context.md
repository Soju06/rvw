# Synthesis context

The normative contract is in [spec.md](spec.md). The 2026-09-09 owner request compares App output on bori#1800 with the controller's explanatory review on bori#1781. The App began with counters, removed inline blockers from the body, and exposed dense reviewer prose with duplicated confirmation reasons. The synthesis pass rewrites retained evidence for repository engineers before publication.

The stage uses the existing tool-less Codex runtime and its policy, watchdog and review-phase environment. A 300-second per-attempt cap, limited further by the run deadline, is the budget for artifact-only writing. The first live runs on a five-finding code pull request (gpt-6-astra, high) measured 71 s for an English document and a 120 s cap exceeded with zero output bytes for the Korean document of the same review, whose finding prose was itself Korean and whose prompt reached 17 KB; Korean output costs roughly two to three times the tokens of English. A cap exceeded is a runtime failure and falls back without a second attempt, so the cap must sit above the realistic Korean generation time or the ko locale would fall back on most reviews. A content-validation failure gets one retry; process failures fall back without a second process. Tool and wall telemetry retain unavailable values rather than inventing zeroes.

The brief says “non-REJECTED confirmed finding” while requiring no findings to disappear. Inputs therefore include confirmed and uncertain groups, excluding rejected groups; uncertainty remains explicit and authoritative in the retained outcome and publication section. Severity and anchors are absent from the generated output schema and remain sourced from merge/outcome data.

The prompt transfers explanatory writing principles: purpose first, concrete consequences, short sentences, source literals intact, respectful written language and a clear first action. Voice belongs to the base-revision presentation snapshot, not auto policy. A deterministic local fixture reproduces the database-double finding supplied in the request; it is a reconstruction, not a live replay of complete bori#1800 artifacts.

Fidelity validation checks exact finding-key membership, literal preservation and internal vocabulary. Output literals must appear byte-for-byte in the corresponding original bodies, adjudication reason/evidence or path. Omission is allowed even for quoted source literals, because adjudication can narrow an original claim. Matching uses raw source spans with token boundaries so existing code can gain backticks without requiring the original formatting. The renderer supplies path/line metadata separately. Source identifiers and quoted literals are exempt from internal-vocabulary checks. Synthesis can reorder findings within their unchanged severity/verdict sections. It cannot prove semantic equivalence, factual completeness or stylistic quality. The retained evidence and deterministic test fixtures support inspection; each prose field now passes the existing language checker with source literals protected before synthesis acceptance, and the publication language gate still controls rendered output. Language diagnostics name every failing field and the configured locale so the one retry can address them together. The checker retains its existing short-prose exemption and language ratios; it does not prove register or stylistic quality.

No discovery/adjudication prompt, replica count, event policy, thread identity, runtime default, external registry, or deployment surface is changed.

## Repository publication controls (2026-09-10)

The owner principle is that choices a consuming repository could reasonably make differently belong in `.rvw/`. The publication subset of the hardcode audit includes two synthesis defects from #95: its universal language example named a Gmail inventory error copied from a bori fixture, and its blanket vocabulary ban rejected the bori #1772 discovery-domain explanation even though finding paths name `life-gmail-discovery-reconciliation`. Source occurrences establish domain vocabulary for that review, and allowed terms offer a repository escape hatch without relaxing literal fidelity.

The anchored presentation snapshot owns `voice.examples`, `voice.allowed_terms` and `synthesis.enabled`; the anchored auto policy owns channels, check conclusions and inline placement. Missing keys preserve existing defaults. Explicit channels take precedence; legacy `publish_state: none` maps to checks only when channels are absent. Disabling checks still terminalizes the mandatory bootstrap check as neutral. Invalid/infrastructure/deadline outcomes cannot be configured to succeed.

Inline selection applies the severity floor, then a highest-severity cap with finding-key ties. Selection precedes living-thread reuse, so reused candidates can reduce newly posted comments below the cap. Body-only findings retain their full explanation. Body-only findings still participate in identity matching, preventing a placement change from being mistaken for fix evidence; their matched threads are excluded from reuse and write plans; historical disappeared findings retain the existing fix-proof rules. `threads.resolve_on_fix` and `threads.reuse_open_thread` apply within that boundary. A zero cap selects no inline candidates. The channel and placement facts remain available in summary artifacts and enabled check details.
